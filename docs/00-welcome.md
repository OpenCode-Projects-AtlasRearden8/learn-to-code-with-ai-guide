# Welcome: You Can Learn to Code

This guide is for the person who has never written a line of code and wonders
if they could. The short answer: yes. The slightly longer answer: yes, and you
do not need to install anything, buy anything, or already be "a computer
person" to start.

Everything in this book assumes three things:

- **You are a beginner.** No prior experience required. We start at zero.
- **You have a browser.** That's the only tool you need. Everything runs in a
  browser tab on any computer — no installs, no setup days.
- **You have an AI to talk to.** Any free AI chat will do: ChatGPT, Claude,
  Gemini, or a local model you already run. We treat it as a patient tutor,
  not an answer machine.

## What this guide covers

Three ideas are the backbone of almost all programming:

1. **Variables** — ways to remember things (Chapter 02)
2. **Loops** — ways to repeat things (Chapter 03)
3. **Functions** — ways to bundle things so you can reuse them (Chapter 04)

Around those three, we walk through:

- Chapter 01: your free browser workbench and your first line of code
- Chapter 05: how to use AI as a *tutor* — hints and questions, not copy-paste
- Chapter 06: what to do when code breaks (it always breaks, and that's fine)
- Chapter 07: where to go next, with free resources

## The most important rule: understanding over copy-paste

AI can write code faster than you can read it. That's a trap for a beginner.
If you copy code you don't understand, you haven't learned to code — you've
learned to paste.

So this book has one rule you'll see again and again:

> Never keep a line of code you can't explain out loud.

If you can't explain a line, ask the AI: "Why did you write that line? What
would break if it weren't there?" Keep asking until you can explain it in your
own words. That's not slower learning — that *is* the learning.

## How each chapter works

Every chapter follows the same shape:

- **The idea** — a plain-English explanation using everyday metaphors
- **Tiny examples** — short and typed by hand, never pasted blindly
- **Tiny exercises** — small enough to finish in a few minutes
- **Try asking your AI** — ready-made prompts that make the AI tutor you
- **Check yourself** — a short list of things you should be able to explain

You never need more than 20 minutes at a sitting. Small and steady beats long
and dramatic.

## How to read this with your AI

Open two things side by side:

1. This guide (in a browser tab).
2. A free AI chat (in another tab).

As you read, bring the AI in constantly. Example conversations you'll have:

- "I don't get the difference between `let` and `const`. Explain it like I'm 12."
- "Give me a tiny practice problem about loops. Don't give me the answer —
  I'll try it and you check my work."
- "Here's my code. It doesn't work. Don't fix it for me. Ask me questions
  until I find the bug myself."

Chapter 05 goes deep on this. It's arguably the most important chapter in the
book — more important than any syntax.

## A note on tone

Programming has a reputation for being intimidating. Ignore that reputation.
Code is just instruction-following, written carefully. Errors are not failure —
they're the computer telling you exactly what it didn't understand. Chapter 06
is entirely about reading those messages kindly.

You are going to feel confused sometimes. Everyone does. Confusion is not a
sign you're bad at this. It's a sign you're at the edge of what you know,
which is exactly where learning happens.

## One habit to start today

Keep a **learning log**: a plain text file or notebook where you write two
lines at the end of each session:

- One thing I learned today
- One thing that confused me today

The confusions are your homework questions for the AI tomorrow. This tiny
habit does more than any course.
